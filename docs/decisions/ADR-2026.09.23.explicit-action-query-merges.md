## ADR-2026.09.23.explicit-action-query-merges — an explicit action's query is merged into, not thrown away; an empty action keeps the platform's replacement

**Date**: 2026-09-23

**Type**: Architectural

**Context**

On a GET submission the HTML Standard replaces the action URL's query with the form data
(§4.10.22.3, "Mutate action URL": "Set parsed action's query component to query"). HTML 2.0
and HTML 4.01 said only that the form data is *appended* to the action, and were silent on an
action that already had a query. The browsers divided over it in 2000: one engine appended,
two replaced, and the replacement won for compatibility. Web Forms 2.0 wrote it down in 2005.
Proposals for richer form actions (URI-template forms, 2007) were declined.

The one case replacement protects is the form with no action. Such a form submits to the
document's own address, whose query is the previous submission's; appending there would make a
search box send `q=cats&q=dogs&q=birds` on its third use.

An explicit action is a different thing. It is a URL the author wrote, and a server that writes
the current found set into an action's query — so that a form stating one more condition needs
to state only that — finds the query discarded. The usual workaround re-states the whole query
as hidden inputs: a second copy of state the server had already expressed once, which must be
kept in agreement with the first.

**Decision**

For GET, HEAD and DELETE, when the submitter's `formaction` or the form's `action` is
non-empty:

1. every pair of the action's query whose key names a submittable control of the form is
   dropped;
2. every other pair is kept, byte-exact and in order;
3. the form's pairs follow.

A control owns its key whether or not it submits anything on this occasion. An unchecked box,
an empty multi-select, a disabled field and a button that is not the submitter all own their
names. A namespaced control owns its wire name. A control inside a `request-header` fieldset
owns its own name.

An empty or absent action keeps the platform's replacement unchanged.

**Rationale**

- **Ownership by control, not by submitted pair.** Were a key owned only when the form sent a
  value for it, unchecking the last box of a key would leave the action's copy standing, and
  the value could never be withdrawn. A form that can state a key is the authority on it; its
  silence says "none".
- **Kept pairs are copied, not re-serialised.** Parsing and re-serialising the action's query
  would turn `%20` into `+` and alter other escapes. A server that treats the query as an
  identity (a cache key, a canonical address) would see a different URL for the same request.
- **The empty action is passed over.** It is the platform's case and the platform's rule
  serves it; no use case argues against it.

**Alternatives Considered**

- *Keep the platform's replacement everywhere.* Rejected: it forces every server that states
  state in an action to state it again in hidden inputs.
- *Plain concatenation.* Rejected: a key present in both the action and the form would be sent
  twice, and a value the form withdrew would survive from the action.
- *Ownership by submitted pairs.* Rejected for the reason above.

**Consequences**

- A form whose explicit action carries a query now sends the pairs of that query its controls
  do not name. A page that relied on the action's query being discarded must drop those pairs
  from the action.
- Hidden inputs that only re-state an action's query can be removed, leaving the action as the
  single statement.
- `index-standalone.html` carries a form with such an action and a form with none, and
  `expectations.json` pins both, including the withdrawal of a key whose boxes are all
  unchecked.
