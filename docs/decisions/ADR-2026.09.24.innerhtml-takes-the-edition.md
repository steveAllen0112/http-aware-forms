## ADR-2026.09.24.innerhtml-takes-the-edition — `innerHTML` replaces the target's inner HTML, including when the response is a new edition of the target

**Date**: 2026-09-24

**Type**: Architectural

**Context**

A page often holds a shell it must keep — an element carrying its own loader, its own attributes,
its own place in the layout — and refreshes only what is inside it. The route that answers the
refresh renders the whole element, so that the route is complete and addressable on its own. The
response is then one element with the same id as the shell.

Before this record, `target="#shell@innerHTML"` put that whole element inside the shell: the
shell nested in itself, the id twice over. `outerHTML` replaced the shell and lost what it
carried. No style did what `innerHTML` names — replace the target's inner HTML.

**Decision**

When the swap is `innerHTML` and the response's primary content is exactly one element whose id
equals the target's id, the target's inner HTML becomes that element's inner HTML. Every other
response is placed as before. The match is on id only.

**Rationale**

- `innerHTML` means the target's inner HTML. Nesting the target inside itself is not a reading of
  that name; it is the accident of treating the response as anonymous markup. The styles that
  insert an element — `beforeend`, `afterbegin` — remain the way to ask for insertion.
- Matching on id alone keeps the rule to the one case it serves. A response rooted at another id,
  or with several roots, is untouched.

**Alternatives Considered**

- *A selector attribute* (htmx's `hx-select`) naming the part of the response to take. Not
  rejected on principle, but a second attribute for what the swap's own name already says; it may
  come later for responses that are not editions of the target.
- *Match on any selector the response root satisfies.* Deferred: wider than the case needs, and it
  would change the placement of responses that work today.

**Consequences**

- A shell refreshed by `innerHTML` from a route that renders the whole element keeps its own
  element and attributes, and takes the new contents.
- A response that relied on nesting a same-id element inside its target — which yields a
  duplicate id, so no valid page did — now receives the inner HTML instead.
