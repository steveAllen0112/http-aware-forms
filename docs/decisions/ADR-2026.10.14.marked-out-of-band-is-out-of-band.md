## ADR-2026.10.14.marked-out-of-band-is-out-of-band — an element marked out of band is out of band, under a retarget too, and is dropped when the page has no element for it

**Date**: 2026-10-14

**Type**: Architectural

**Context**

`swapResponse` sorts the top-level elements of a response into primary content and out-of-band
updates. Up to 3.3.2 it did so by id alone. Without a retarget, an element whose id is carried
by an element on the page, other than the target and not inside a target the primary swap will
wipe, replaced that element; every other element was primary content. Under a retarget
(`X-Retarget`, or `HX-Retarget` with the htmx interop loaded) the id rule was switched off and
the whole response was primary content, because a response that refreshes a whole container
carries children whose ids are already on the page, and pulling them out would leave the
container empty.

The marker attributes (`data-swap-oob`, and `hx-swap-oob` with the interop) took no part in
that sorting. They were read only to find out-of-band content wrapped in a `<template>`. So
under a retarget an element the server had explicitly marked out of band was put into the
retargeted element with the primary content; a marked element whose id was nowhere on the page
became primary content in either arm; and the marker's value was ignored, so a marked element
always replaced the element on the page.

htmx treats an element carrying `hx-swap-oob` as out of band whatever the main swap is doing,
including under `HX-Retarget`, and drops one whose target it cannot find. The marker's value
names the swap: `true` and `outerHTML` replace the element, `innerHTML` fills it.

**Decision**

Before the primary content is chosen, every top-level element of the response that matches
`HTTPAwareForm.oobSelector` is taken out and applied on its own, with or without a retarget:

1. When no element on the page carries its id, it is dropped, with a `console.warn`. It is never
   primary content.
2. `data-swap="morph"` on it morphs the element on the page, as before.
3. Otherwise the marker's value is the swap. `innerHTML` replaces the inner HTML of the element on
   the page, which keeps its own tag, attributes and listeners. Any other value — `true`,
   `outerHTML`, an empty value — replaces the element.
4. The edit state inside the element is captured before and restored after, as for any other
   out-of-band replacement, and the element that results is reported in the `oobTargets` of
   `http-aware:swapped`.

Unmarked elements are sorted exactly as before: by the id rule without a retarget, and as
primary content under one.

**Rationale**

- **A marker is a statement by the server.** An id shared with the page is a guess at intent,
  which is why the retarget arm switches it off; a marker is not a guess, and switching off the
  guess should not switch off the statement.
- **The same reading as htmx.** A server written for htmx, and a page migrating from it, get the
  behaviour they were written against.
- **Dropping beats misplacing.** A marked element with nowhere to go would otherwise land inside
  the primary target, where it duplicates or displaces content the server did not mean to put
  there.
- **`innerHTML` keeps the shell.** A page often holds an element it must keep — its own loader,
  attributes, visibility state, listeners — and refreshes only what is inside it. Replacing it
  loses all of that; filling it keeps it.

**Alternatives Considered**

- *Leave marked elements to the id rule, and add a header that switches the rule back on under a
  retarget.* Rejected: it puts on the server a second statement of what the marker already says.
- *Honour every htmx swap value* (`beforeend`, `afterbegin`, `delete`, and the `style:selector`
  form that names a different element). Not done here: no use has needed them. They are read as
  "anything else" today and replace the element; a later record may extend the reading.

**Consequences**

- Under a retarget, a marked element no longer appears inside the retargeted element; it updates
  its own element, or is dropped.
- Without a retarget, a marked element whose id is not on the page is dropped where it used to
  become primary content; a marked element whose id is the target's own, or lies inside a target
  the primary swap wipes, is now applied out of band like any other marked element before the
  primary swap runs (so a marked replacement of the target itself leaves the primary swap writing
  into the detached element); and `innerHTML` is honoured where every marked element
  used to replace its element.
- A marker value of the `style:selector` form, or an insertion style, replaces the element rather
  than doing what htmx would do with it.
- `index-standalone.html` carries a retargeted and an unretargeted form against a response that
  holds a replacing, a filling, a homeless and an unmarked element, and `expectations.json` pins
  each, including the unmarked element's unchanged behaviour in both arms.
