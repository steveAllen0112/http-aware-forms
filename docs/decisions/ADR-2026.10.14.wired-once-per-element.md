## ADR-2026.10.14.wired-once-per-element — a form's listeners are attached once for its lifetime, however often it is connected

**Date**: 2026-10-14

**Type**: Architectural

**Context**

`connectedCallback()` attached the form's submit listener with
`this.addEventListener('submit', this._handleNativeSubmit.bind(this))` and then called
`_installAutoSubmit()`, which attached its `input`/`change` listeners with a closure made on the
spot. A customized built-in element's `connectedCallback` runs every time the element is
connected, not once, and a listener on the element survives a disconnect. Each connection
therefore added one more submit listener and one more set of autosubmit listeners, and since
`bind` and the closure made a new function every time, `addEventListener` had no way to see them
as the same listener.

A form is connected more than once whenever something moves it. The library moves nodes itself:
`_morphChildren` reorders a matched node with `insertBefore`, which disconnects and reconnects
it. An application moves them too, for instance when a drag reorders rows that each hold a form.

In use, one click on a submit button sent two requests a millisecond apart, and one click on a
DELETE submitter sent two DELETEs. `requestSubmit` aborts the form's request in flight, but the
first request had already gone. Where an application disabled the submitter on
`http-aware-submitted` — a common guard that allows one request at a time — the second handler
built its body after the submitter had been disabled, so the submitter's pair was missing and
the server rejected the request for a missing field.

With `debounce` set, the duplicate autosubmit listeners happened to share one timer map, so the
second cancelled the first's timer and one request went out. Without `debounce` every change
submitted once per listener set.

**Decision**

Each listener the form attaches to itself is a function made once, with the element: two
instance fields, `_onNativeSubmit` and `_onAutoSubmitEdit`, each delegating to a method.
`connectedCallback` attaches those same functions. `addEventListener` ignores a listener already
registered for the same event and phase, so a second connection adds nothing.

`autosubmit` and `debounce` are read at every connection, as they were, and the listeners are
brought to match: an event no longer named loses its listener, a named one keeps the listener it
has, and the delay is stored on the element for the handler to read. The per-control timer map
is made once and kept across connections.

**Rationale**

- **The platform's own deduplication.** Passing the same function again is defined to be a
  no-op, so the guarantee does not rest on a flag the library keeps in step with the element's
  state. A form connected ten times has one submit listener because the platform will hold only
  one.
- **Reading the attributes at each connection is kept.** The code has always read `autosubmit`
  and `debounce` when the form connects, and never on a change made while it is connected. A
  form whose attributes are changed while it is out of the page now takes the new values when it
  returns, with its old listeners removed. Before, it gained the new set beside the old one,
  which was the same defect. A change made while the form is connected still waits for the next
  connection.
- **Unchanged events keep their listener.** The listener set is adjusted, not removed and added
  afresh, so a move does not change the order in which the form's own listeners run relative to
  an application's.
- **The timer map survives a move.** A control's pending debounce timer, set before a move, is
  still found and cleared by the next edit after it; a fresh map would leave it to fire beside
  the new one.

**Alternatives Considered**

- *A `_wired` flag checked in `connectedCallback`.* Rejected: it would freeze `autosubmit` and
  `debounce` at the first connection, which narrows what the code did before, and it adds a
  piece of state to keep honest where the platform already supplies the guarantee.
- *Remove every listener in `disconnectedCallback` and add them again on connection.* Rejected:
  it changes listener order on every move, and it does nothing for a function made afresh each
  time unless the function is kept anyway, at which point the removal is not needed.

**Consequences**

- One click is one request, and one change under `autosubmit` is one request, however often the
  form has been moved.
- An application that worked around the duplicate submission, by debouncing its own submit
  guard or by tolerating the second request, may drop the workaround.
- `RequestHeader`, `QueryParam` and `NameSpace` have no `connectedCallback` and attach nothing,
  and `http-aware-htmx.js` defines no element, so nothing else in the library had this shape.
- `expectations.json` pins a form moved by reinsertion and by the morph, twice each, and an
  autosubmit form moved both ways, each counting the requests sent and the
  `http-aware-submitted` events dispatched.
